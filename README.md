# 강의 PPT → 교재 Markdown 변환 (`ada_pptx2md`)

`AppliedDataAnalisis_1~3.pptx`(실제로는 **1~8장 560장**)를 장별 폴더 · 절별 md ·
그림 서브폴더 구조의 교재로 옮긴 작업이다.

```
교재_ppt_md/
├── 00_강의개요.md                    ← 전체 목차 (각 절 md 로 링크)
├── _집필지침.md                      ← 재작성 규칙 (2학기 개정 때도 이 규칙을 따르면 된다)
├── ch01_DL기반데이터분석소개/
│   ├── 00_1장개요_장개요.md
│   ├── 1.1_DL기반Data분석.md
│   ├── 1.2_딥러닝개요.md
│   ├── images/                       ← 본문이 실제로 참조하는 그림만
│   └── _원문/1.1_원문.txt             ← 슬라이드 원문 덤프 (집필 재료 · 대조용)
├── ch02_관측공간/ … ch08_판단프레임워크/
└── _tools/
    ├── ada_pptx2md/                  ← 변환 라이브러리
    └── 교재_ppt_md_변환_테스트.ipynb   ← 전체 기능 테스트 노트북
```

## 왜 pandoc 이나 PDF 추출을 쓰지 않았나

docx 변환 때 텍스트박스가 통째로 사라졌던 것과 **같은 함정이 pptx 에도 있다.**

1. **`mc:AlternateContent` 누락 — 가장 치명적.** 파워포인트는 수식이 들어간 도형을
   `mc:AlternateContent` 로 감싼다. python-pptx 의 `slide.shapes` 순회는 이 요소를
   **통째로 건너뛴다.** 슬라이드 329·331 은 python-pptx 기준 "빈 슬라이드"로 보이지만
   실제로는 44KB·97KB 분량의 본문이 들어 있다. 그래서 lxml 로 슬라이드 XML 을 직접
   문서 순서대로 순회하도록 구현했다.
2. **수식 구조 붕괴.** 단순 텍스트 추출은 `Recall(i)=TP_i/(TP_i+FN_i)` 를 뭉갠다.
   docx 변환기의 `omml.py` 를 그대로 재사용해 OMML 트리를 LaTeX 로 복원한다
   (전체 1,176개).
3. **유니코드 수학 알파벳.** 수식 편집기가 기울임을 `𝑪`, `𝒊` 같은 U+1D400 대역
   문자로 저장한다. 그대로 두면 LaTeX 렌더러가 폰트를 못 찾고 검색도 안 된다.
   NFKC 로 정규화한다.
4. **확장자와 내용의 불일치.** 삽입 그림 중 15장은 확장자가 `.tmp` 인데 내용은 PNG,
   2장은 `.tiff` 다. 매직 넘버로 판정해 저장하고 필요하면 png 로 변환한다.
5. **숨김 슬라이드.** 66·232 번이 숨김이라 PDF 는 558쪽이다. 슬라이드 번호를
   PDF 페이지로 바꿀 때 이 어긋남을 보정해야 한다.

## 슬라이드 경계를 다시 확정한 것

기존 `_작업관리/04_주차별_소스매핑.md` 의 표를 그대로 쓰지 않고, 560장의 제목을
전부 훑어 재확정했다. 바로잡은 것:

| 항목 | 기존 표 | 실제 |
|---|---|---|
| 1.2 범위 | 16~38 | **16~28** (29~30 은 1장 review, **31~38 은 2장 도입부**) |
| 6.2 범위 | 404~444 | **404~438** (**439~444 는 7장 Explainability 도입부**) |
| 8장 소스 | `_4~8.pptx` 361~370 | **main pptx 551~560** (양쪽 10장 본문이 완전히 일치) |

`config.coverage()` 로 560장 전부가 빠짐없이 한 번씩만 배정됐음을 검증한다.

## 쓰는 법

```python
from ada_pptx2md import build_all, report, validate

print(report(build_all()))          # 슬라이드 추출 · 그림 저장 · 개념도 렌더링
print(validate.report(validate.check_all()))   # 링크·보존율 검증
```

`build_all()` 이 만드는 것은 **재료**(`_원문/*.txt` 와 `images/`)까지다.
교재 문장 자체는 `_집필지침.md` 를 따라 사람이(또는 LLM 이) 쓴다.

## 그림 두 종류

| 표기 | 뜻 | 처리 |
|---|---|---|
| `s327_01.png` | 슬라이드에 **삽입된 그림** (그래프·스크린샷) | 원본 그대로 추출 |
| `fig329.png` | 도형·화살표로 **그린 개념도** — 추출할 파일이 없다 | LibreOffice → PDF → 해당 쪽만 PNG |

개념도 판정 기준: SmartArt·차트가 있거나, 연결선 2개 이상, 또는 텍스트를 가진
도형 4개 이상. 154장이 걸렸고 그중 22장을 본문에 썼다. 나머지는 본문 글자를
그대로 다시 찍은 것이라 중복이어서 `_슬라이드캡처_미사용/` 으로 빼 두었다.

## 검증 결과

- 슬라이드 배정 560/560, 누락·중복 0
- 깨진 이미지 링크 0 (그림 링크 557개)
- 원문 보존율 절 평균 88% (교재체로 다시 쓰므로 100% 는 나올 수 없다.
  명사구 표본이 md 에 남아 있는 비율을 잰 값이다.)

## 주의

- **이제부터는 md 가 주(主) 문서다.** pptx 를 고치고 다시 변환하면 md 수정분이
  덮어써진다. 둘 중 한쪽만 편집할 것.
- `_원문/*.txt` 는 대조용이므로 지우지 말 것. 2학기 통합 때 doc·영상 전사문과
  세 소스를 맞대볼 기준이 된다.
